# 观点复盘

只给自己看的判断账本：把做研究时下的判断记下来，到兑现时间后回头看对不对，把教训攒起来。

## 页面

| 页 | 内容 |
|---|---|
| 首页 | 今日简报：在跟踪几条、几条到期；记一条判断；未来 180 天时间带；到期待填；兑现日程；战绩；最近复盘；上一条教训 |
| 账本 | 主功能。一张表：# / 事项 / 我的判断 固定在前三列，跟踪信号 / 创建时间 / 兑现时间 / 实际情况 / 复盘 可显示隐藏、调顺序；点表头排序；搜索正文、标签、出处；格子点击即写，回车保存 |
| 日历 | 按月列兑现时间，外加手工加的开奖事件 |
| 复盘 | 战绩、错因分布、错因表（自己维护）、教训库、带教反馈（标签含「带教」的行） |
| 设置 | 名字、规则说明、导出 Markdown / JSON、容量 |

## 规则（都在数据库触发器里，前端改不动）

- 「事项 / 判断 / 跟踪信号 / 兑现时间 / 怎么判 / 类型」创建 24 小时后锁定。想改口径：行菜单「新开一行替代」，旧行照样算。
- 「实际情况 / 复盘 / 判定 / 错因」到兑现时间（北京时间当天起）才能写。
- 把握只能在兑现前改，每次改动自动记进「把握记录」。
- 没有删除，只有撤回；撤回的仍在账本里，到期照样算。
- 理由 / 失效信号 / 出处 / 数据源 / 标签随时可改，旧值留在「修订记录」里。

## 结构

纯静态：`index.html` + `style.css` + `app.js`，数据在 Supabase（登录用邮箱验证码）。`config.js` 里只放项目 URL 和 anon key。数据库结构和每日备份在私有仓库 `guandian-fupan-ops`。

本地看：在这个目录起一个静态服务（例如 `python3 -m http.server 8000`），打开 `http://localhost:8000/`。

## 发布

推到 `main` 即上线（GitHub Pages 从 main 根目录发布）。推之前先按全局规则截图预览。
